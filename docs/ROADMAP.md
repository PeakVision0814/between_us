## 当前阶段：阶段 8 — 用户资料与双人身份展示（收尾中）

本阶段已完成资料字段补全、资料引导和“我们”页主结构收束。当前只保留收尾项，不再展开已实现的过程型细项。

### 8.3 个人资料编辑页

目标：已注册用户可以随时修改自己的昵称、性别、生日。

- 从“我们”页 Hero 右上角个人信息入口进入独立编辑页
- 只编辑本人资料，不改对方资料
- 保存后同步到 Supabase `profiles` 表和 `AppController`

### 8.4 双人身份补完

目标：在双人模式下补齐身份展示与作者标识。

- 单人模式只保留轻量邀请提示和展示态，不继续扩展复杂可操作体验
- 随记、计划、日历事件在双人模式下显示作者昵称
- “我们”页在安全边界内展示 TA 的资料信息
- RLS 策略允许同一 `couple space` 的活跃成员互相查看必要 profile 字段

### 8.5 “我们的空间”卡片视觉重构

目标：继续打磨”我们”页主页面，但只聚焦”我们的空间”模块，让它更接近 `docs/风格参考图.png` 中”模块标题 + 查看更多 + 4 个入口按钮”的简洁模块结构。

本轮只做：

- 重构”我们的空间”标题下方的模块入口卡片
- 参考风格图中的发光边框、半透明 surface、柔和 icon badge、信息卡层次
- 优先服务双人模式下的共同空间感
- 默认展示 4 个简洁入口按钮
- 右上角提供”查看更多”
- 单人模式不在该卡片重复展示邀请操作

### 8.6 空间模块精简为单入口

目标：将”我们的空间”模块卡从 4 入口精简为 1 个”空间状态”入口，移除与 Dock 主导航重复的日历、计划、随记、设置入口。

本轮只做：

- 模块卡内只保留”空间状态”一个图标入口
- 移除”查看更多 >”
- 移除日历、计划、随记、设置四个旧入口
- 单人态”空间状态”不可点击
- 双人态”空间状态”可点击（详情页后续单独开发）

本轮明确不做：

- 不改顶部关系 Hero
- 不改个人资料页 / TA 资料页 / 设置页
- 不新增数据库字段
- 不新增头像上传、照片、等级、图标格等参考图里的虚构功能
- 不新增关系起点编辑、纪念日提醒或日历联动
- 不在“我们的空间”卡片里重复生成邀请码 / 输入邀请码 / 展示邀请码
- 不扩散到首页、日历、计划笔记

## 阶段 9：敏感数据能力与生活增强

目标：在共享能力稳定后，再逐步增加更敏感、更贴近日常生活的功能。

前提：性别字段已就位，用于判断经期记录的功能权限。

范围：

- 经期记录首版
- 仅支持手动记录，不做复杂预测
- 仅 gender='female' 的用户可以记录
- gender='male' 的用户只能查看（前提是对方明确开启共享）
- 在日历中展示经期相关信息，但和纪念日、约会保持视觉区分
- 可逐步增加计划提醒、约会提醒等增强能力

完成标准：

- 经期记录可以手动添加和查看
- 共享权限逻辑明确且可控
- 文案和交互不会让用户产生被监控感
- 敏感数据不会因为默认设置而意外暴露

## 阶段 10：稳定性与私测 Beta

目标：在扩展更多模块前，先验证整体产品是否真的被情侣自然使用。

前提：手机号验证码登录（SMS OTP）必须在本阶段开始前完成。国内私测用户习惯手机号登录，仅靠邮箱验证码不够。

范围：

- 完善关键逻辑测试、共享权限测试、时间逻辑测试
- 改善离线行为、错误提示和重试机制
- 复核中英文文案质量和三种主题体验
- 小范围私测，收集真实情侣反馈
- 重点验证首页、日历、计划笔记、我们这 4 个页面的使用频率和边界清晰度

私测重点观察：

- 首页是不是足够顺手
- 日历和计划笔记会不会混
- 我们页是否真的能承接个人与双人设置
- 经期记录共享是否让用户感到安心
- 用户会不会觉得它太工具，还是刚好实用

完成标准：

- 关键场景的失败状态可见且可恢复
- 测试覆盖关键逻辑
- 私测反馈能产出明确的保留、调整、删除决策
- 团队可以基于证据决定下一批扩展模块
