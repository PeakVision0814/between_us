## 当前阶段：阶段 8 — 用户资料与双人身份展示（收尾中）

本阶段已完成资料字段补全、资料引导和“我们”页主结构收束。当前只保留收尾项，不再展开已实现的过程型细项。

### 8.3 个人资料编辑页

目标：已注册用户可以随时修改自己的昵称、性别、生日。

- 从“我们”页“我的资料”区域进入独立编辑页
- 只编辑本人资料，不改对方资料
- 保存后同步到 Supabase `profiles` 表和 `AppController`

### 8.4 双人身份补完

目标：在双人模式下补齐身份展示与作者标识。

- 单人模式首页邀请提示卡片
- 随记、计划、日历事件在双人模式下显示作者昵称
- “我们”页在安全边界内展示 TA 的资料信息
- RLS 策略允许同一 `couple space` 的活跃成员互相查看必要 profile 字段

### 视觉系统升级（`style-refresh` 分支，跨页面支线）

目标：把全 App 统一成温暖、柔和、情绪化的情侣产品视觉系统，而不是只改某一页。

- 视觉目标：温暖、轻盈、成熟、长期耐看、低饱和、低压迫感
- 执行方式：先做全局视觉基线，再逐页替换为统一组件语言
- 重点范围：主题色板、渐变、卡片、阴影、圆角、文字层级、背景氛围、基础组件样式、亮暗模式
- 约束：不在这一支线上新增业务功能，不把风格改造和功能迭代混在一起

#### 第一轮（已完成）

- 已完成视觉基线层
- 已完成认证链路试点（登录页 / 注册页 / 资料设置引导页）
- 未扩散到其他业务页面

#### 第二轮（下一步）

目标：把“我们”页做成视觉系统的第一个业务标杆页，在不增加新功能的前提下，明显建立目标中的陪伴感、私密空间感和亮暗双情绪体验。

本轮只做：

- 改造“我们”主页面视觉表现
- 保留现有“主页面 + 二级设置入口”的结构，不改信息架构
- 将新视觉明确落到：
  - 顶部关系区
  - 我的资料
  - TA / 邀请态
  - 我们的空间
  - 设置与更多入口
- 在双人模式和单人模式下都体现更强的氛围感和层次感
- 为后续首页、日历、计划笔记提供可复用的业务页视觉样板

本轮明确不做：

- 不新增业务功能
- 不新增个人资料编辑页
- 不新增 TA 的真实性别 / 生日读取
- 不修改二级设置页功能结构
- 不改首页、日历、计划笔记
- 不引入对外部产品的直接复刻

## 阶段 9：敏感数据能力与生活增强

目标：在共享能力稳定后，再逐步增加更敏感、更贴近日常生活的功能。

前提：性别字段已就位，用于判断经期记录的功能权限。

范围：

- 经期记录首版
- 仅支持手动记录，不做复杂预测
- 仅 gender='female' 的用户可以记录
- gender='male' 的用户只能查看（前提是对方明确开启共享）
- 在日历中展示经期相关信息，但和纪念日、约会保持视觉区分
- 可逐步增加计划提醒、约会提醒等增强能力

完成标准：

- 经期记录可以手动添加和查看
- 共享权限逻辑明确且可控
- 文案和交互不会让用户产生被监控感
- 敏感数据不会因为默认设置而意外暴露

## 阶段 10：稳定性与私测 Beta

目标：在扩展更多模块前，先验证整体产品是否真的被情侣自然使用。

前提：手机号验证码登录（SMS OTP）必须在本阶段开始前完成。国内私测用户习惯手机号登录，仅靠邮箱验证码不够。

范围：

- 完善关键逻辑测试、共享权限测试、时间逻辑测试
- 改善离线行为、错误提示和重试机制
- 复核中英文文案质量和三种主题体验
- 小范围私测，收集真实情侣反馈
- 重点验证首页、日历、计划笔记、我们这 4 个页面的使用频率和边界清晰度

私测重点观察：

- 首页是不是足够顺手
- 日历和计划笔记会不会混
- 我们页是否真的能承接个人与双人设置
- 经期记录共享是否让用户感到安心
- 用户会不会觉得它太工具，还是刚好实用

完成标准：

- 关键场景的失败状态可见且可恢复
- 测试覆盖关键逻辑
- 私测反馈能产出明确的保留、调整、删除决策
- 团队可以基于证据决定下一批扩展模块
